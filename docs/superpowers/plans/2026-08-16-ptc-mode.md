# PTC 模式实施计划

> 配套设计文档：[2026-08-16-ptc-mode-design.md](../specs/2026-08-16-ptc-mode-design.md)
> 日期：2026-08-16 ｜ 状态：Draft

## 目标

为项目新增第三种执行模式 **PTC（Programmatic Tool Calling，程序化工具调用）**，参考 deepseek-harness 的 Code Mode 实现：模型编写 TypeScript 程序，经 `run_code` 工具在 worker 线程沙箱中批量执行工具调用，减少模型↔工具往返与 Token 消耗。

## 关键决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 模式切换方式 | 环境变量 `AGENT_MODE` + 工厂函数 | 与现有配置风格一致，零运行时改动 |
| 沙箱实现 | Node `worker_threads` 每次全新 Worker | 与 dsh 参考实现一致；进程内隔离成本低 |
| 类型剥离 | `node:module` 的 `stripTypeScriptTypes`（回退 `ts.transpileModule`） | 位置保留，错误行号一致 |
| 工具呈现 | `tools["name"](args)` 引号对象键 | 任意工具名零别名/碰撞 |
| 降级 | 错误回喂自纠；连续 3 次失败进 fallback | 与 dsh 失败反馈思路一致，保证体验 |
| 与 plan 模式关系 | v1 互斥 | 组合语义留待 M5 |
| finalize/fallback | 结构复用、实现不复用：提取 `src/agent/graph-utils.ts` 共享纯函数（extractFinalAnswer / buildIterationExhaustedSummary），PTC 注入 `formatPtcStatsReport` | 状态字段、统计来源、触发条件均不同，不能直接调 GraphAgentExecutor 类方法 |
